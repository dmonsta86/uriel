# Paper Builder reference

The Paper Builder keeps a manuscript as plain files next to the project record.
It refuses to build a version whose numbers, citations, quotations, or claims
have drifted away from their evidence. It is experimental; see the boundaries at
the end of this page and in [Known limitations](LIMITATIONS.md). For the
end-to-end workflow, start with the [research protocol](RESEARCH_PROTOCOL.md).

## Commands

```text
uriel paper init        --root . [--article-type empirical|replication|negative_result|methods|resource|review] [--title ...]
uriel paper check       --root . [--profile draft|submission]      # read-only; exit 2 on blockers
uriel paper build       --root . [--profile draft|submission]      # refuses unless the check passes
uriel paper verify-build --root .                                  # read-only; exit 2 when stale
uriel paper lint        --root . --file PATH                       # prose + statistics lint of any text file
uriel paper dp-add      --root . --id ID --artifact PATH --description TEXT LOCATOR [options]
uriel paper dp-refresh  --root . --id ID [--confirm-change]
uriel paper review      ...                                        # the existing read-only fidelity review
```

## Layout

```text
paper/
  paper.json          uriel.paper.v1: title, article type, ordered sections, word limits
  sections/NN_id.md   one Markdown file per section
  datapoints.json     uriel.datapoints.v1: every reported number
  references.json     uriel.references.v1: every cited work
  build/              generated by `paper build`; excluded from the source inventory
    manuscript.md     rendered manuscript with numbered citations and a reference list
    NUMBER_TRACE.md   every rendered number with its source token, artifact, digest, and locator
    BUILD_RECEIPT.json uriel.paper_build.v1: digests of every input, artifact, and output
```

`paper init` never overwrites an existing manuscript. Each section starts with an
HTML comment that holds the section checklist and context copied from
`uriel.project.json`: the question, hypothesis, claims, alternatives, and
limitations. Comments are ignored by every check and removed from the build.

Each section in `paper.json` has a `kind` (abstract, introduction, methods,
results, discussion, limitations, conclusion, statements, other) and a
`number_policy`:

| Policy | Default for | Meaning |
|---|---|---|
| `bound` | abstract, results, conclusion | Every numeral must come from `{{dp:ID}}` or `{{lit:...}}` |
| `cited_or_bound` | introduction, discussion, limitations, other | A sentence with a numeral needs a citation or a datapoint |
| `free` | methods, statements | Numerals are not policed (design constants, dates) |

Years (1800–2099), labels such as `Table 2` or `Figure 3`, coverage levels such
as `95% CI`, headings, and list numbers are never flagged.

## Markup

| Markup | Meaning | Built output |
|---|---|---|
| `{{dp:ID}}` | a verified datapoint | its formatted value |
| `{{lit:TEXT}}` | a deliberate literal, not a result | `TEXT` |
| `[@key]`, `[@a; @b, p. 4]` | citations of `references.json` keys | `[1]`, `[1, p. 4; 2]` |
| `[claim:C1]` | ties the sentence to claim C1 in the project record | removed |

Unknown `{{...}}` markup, unbalanced braces, unknown keys, unknown claims, and
unregistered datapoints always block.

## Datapoints

Register a value with `dp-add`. Uriel opens the artifact, extracts the value,
records the artifact's SHA-256 and the exact source token, and writes the entry.
You never type the value.

```text
uriel paper dp-add --root . --id n_total --artifact artifacts/summary.csv \
  --csv-column value --csv-row metric=n_total --kind count --description "Participants analysed"
uriel paper dp-add --root . --id effect --artifact artifacts/model.json \
  --json-pointer /effect/estimate --kind estimate --format .2f --description "Mean difference in ms"
uriel paper dp-add --root . --id r2 --artifact artifacts/fit.log \
  --text-regex "R2 = ([0-9.]+)" --kind proportion --description "Model R squared"
```

**Locators** must match exactly one value: one CSV/TSV cell (by `--csv-row
KEY=VALUE` filters or `--csv-row-index`), one JSON Pointer to a number or string,
or one regular-expression match with exactly one capture group (optionally on
one `--text-line`). Artifacts must be strict UTF-8, at most 64 MiB, part of the
project's source inventory, and outside `paper/`.

**Formats** (rounding is half-up): `raw` (exact source token, default), `d`,
`,d`, `.Nf`, `,.Nf`, `.N%` (value × 100), a trailing `~` to drop the leading
zero (`.45`), and `apa_p` (`p = .023` or `p < .001`).

**Kinds** set sanity bounds: `count` (whole, ≥ 0), `proportion` [0, 1],
`percent` [0, 100], `p_value` [0, 1], `correlation` [−1, 1], `sd`/`se`/`variance`
(≥ 0). `min`/`max` add explicit bounds. A `mean` may declare
`--grim-n N` (or `dp:ID`) and `--grim-items K` for the GRIM test.

**Relations** live in `datapoints.json` under `relations`:

```json
{"type": "sum", "parts": ["n_a", "n_b"], "total": "n_total"}
{"type": "ratio", "numerator": "n_a", "denominator": "n_total", "result": "pct_a", "scale": 100}
{"type": "ci", "lower": "lo", "estimate": "est", "upper": "hi"}
{"type": "le", "left": "median", "right": "max"}
{"type": "equal", "ids": ["n_from_model", "n_from_summary"]}
```

`ratio` tolerance defaults to half a unit of the result's displayed precision.

**Provenance:** a datapoint whose artifact lives under `artifacts/` should have
been written or kept by a verified passing `uriel run`. If it came from
elsewhere, say so with `--provenance "external: REASON"` (at least 25
characters). Otherwise the submission profile blocks.

**Changing data:** when an artifact changes, every datapoint bound to it is
stale. `dp-refresh` re-binds it. If the value itself changed, the command
refuses until you add `--confirm-change`, and the ledger records the old and new
values.

## References

```json
{
  "key": "smith2020",
  "authors": ["Smith, J.", "Lee, K."],
  "year": 2020,
  "title": "File sets in build systems",
  "venue": "Journal of Builds",
  "doi": "10.1234/jb.2020.1",
  "artifact_path": "sources/smith2020.txt",
  "sha256": "…",
  "verification": {"status": "held", "checked_on": "2026-10-01", "note": "Opened the publisher PDF; saved page 3 text."}
}
```

| Status | Meaning |
|---|---|
| `held` | a project-local copy exists at `artifact_path`, its bytes match `sha256`, and a person attested (`checked_on` ISO date and `note`) that it is the published work |
| `metadata_checked` | a person checked the metadata against the publisher record (`checked_on` and `note` required) |
| `unverified` | default; citing it blocks the submission profile |

A verified status is always a human attestation. A matching file alone never
upgrades a reference, because an assistant can write a plausible file as easily
as it can cite one. A held copy with matching bytes still lets Uriel verify
quotations, even when the reference is unverified.

Quotations of six or more words followed by a citation are matched verbatim
against the cited held source. Matching normalizes whitespace, curly quotes, and
non-breaking spaces, and accepts `...`/`…` between fragments that appear in
order. Held sources must be UTF-8 text (`.txt`, `.md`, `.tex`, `.html`, …). For a
PDF, save a text excerpt of the quoted page under `sources/`. Long quotations
without a citation are also reported.

## Check codes

Levels: **grave** findings block every profile, **submission** findings warn in
`draft` and block `submission`, and **style** findings only warn.

| Area | Grave | Submission | Style |
|---|---|---|---|
| Structure | `PAPER_MANIFEST_INVALID`, `SECTION_FILE_MISSING`, `MARKUP_INVALID` | `TITLE_MISSING`, `SECTION_EMPTY`, `WORD_LIMIT_EXCEEDED`, `STATEMENT_MISSING`, `RESULTS_WITHOUT_DATAPOINTS` | `SECTION_NOT_IN_MANIFEST` |
| Numbers | `DATAPOINT_MARKER_UNKNOWN`, `DATAPOINT_ARTIFACT_MISSING`, `DATAPOINT_ARTIFACT_STALE`, `DATAPOINT_VALUE_MISMATCH`, `DATAPOINT_LOCATOR_FAILED`, `DATAPOINT_SANITY_VIOLATION`, `DATAPOINT_GRIM_INCONSISTENT`, `DATAPOINT_RELATION_VIOLATED`, `DATAPOINT_ARTIFACT_NOT_MANIFESTED` | `UNBOUND_NUMBER`, `UNSOURCED_NUMBER`, `DATAPOINT_NOT_FROM_RECORDED_RUN`, `DATAPOINT_ROUNDED_TO_ZERO` | `DATAPOINT_UNUSED` |
| Statistics | `STAT_DECISION_INCONSISTENT`, `STAT_IMPOSSIBLE_P`, `STAT_IMPOSSIBLE_CORRELATION`, `STAT_NEGATIVE_DISPERSION`, `STAT_CI_BOUNDS_REVERSED`, `STAT_ESTIMATE_OUTSIDE_CI`, `STAT_COUNT_EXCEEDS_TOTAL` | `STAT_P_INCONSISTENT`, `STAT_PERCENT_COUNT_MISMATCH`, `STAT_P_REPORTED_AS_ZERO`, `STAT_PERCENT_OF_EXCEEDS_100` | |
| Sources | `CITATION_KEY_UNKNOWN`, `CITATION_SYNTAX_INVALID`, `REFERENCES_INVALID`, `REFERENCE_KEY_DUPLICATE`, `REFERENCE_YEAR_IMPLAUSIBLE`, `REFERENCE_SOURCE_MISSING`, `REFERENCE_SOURCE_STALE`, `QUOTE_NOT_IN_SOURCE` | `REFERENCE_UNVERIFIED`, `REFERENCE_INCOMPLETE`, `REFERENCE_DOI_INVALID`, `REFERENCE_DOI_DUPLICATE`, `QUOTE_UNVERIFIABLE`, `QUOTE_UNATTRIBUTED` | `REFERENCE_UNUSED` |
| Claims | `CLAIM_ANCHOR_UNKNOWN` | `CLAIM_ANCHOR_UNSUPPORTED`, `CLAIM_NOT_REPORTED`, `COUNTEREVIDENCE_NOT_DISCUSSED`, `CAUSAL_LANGUAGE_WITHOUT_IDENTIFICATION` | |
| Prose | `ASSISTANT_RESIDUE` | `PLACEHOLDER_TEXT`, `STOCK_PHRASE`, `HYPE_LANGUAGE`, `PROOF_LANGUAGE`, `UNSOURCED_ATTRIBUTION`, `REASONING_PATTERN`, `EMOJI`, `FILLER_DENSITY` (when dense) | `FILLER_WORD`, `HEDGE_STACK`, `REPETITIVE_OPENER`, `TRANSITION_CHAIN`, `EM_DASH_DENSITY`, `LIST_IN_PROSE_SECTION`, `INLINE_BOLD_LABEL` |
| Plan | `PLAN_LOCK_DAMAGED`, `PREREGISTRATION_CLAIM_UNSUPPORTED` | `PLAN_CHANGED_SINCE_LOCK`, `PLAN_NOT_LOCKED` (once passing runs exist) | `PLAN_REVISED_AFTER_RESULTS` |

Every finding carries its file and line where one exists, an excerpt, and
exactly three repair options.

## Build and verification

`paper build` runs the check at the chosen profile and refuses on any blocker.
It then renders the sections in order and replaces markup. Citations are
numbered by first appearance, a reference list is appended, claim anchors and
comments are removed, and `NUMBER_TRACE.md` and `BUILD_RECEIPT.json` are
written. Rendering is deterministic, so the same inputs produce the same bytes.

`paper verify-build` re-renders from the current sources and compares the
result with the receipt. It reports `STALE` with reasons when any section,
registry, artifact, cited source, the project record, or an output file has
changed.

## Boundaries

- Markdown is the only output format. DOCX and PDF export are not implemented.
- A verified datapoint proves which bytes a number came from and that it was
  copied exactly. It does not prove that the analysis was appropriate or correct.
- Statistical recomputation covers reported t, F, chi-square, r, and z tests in
  APA-like notation. It cannot see tests written in other notations, and it does
  not judge whether a test was the right one.
- Quote checks prove verbatim presence in the held copy, not that the copy is
  authentic or that the quote is used fairly.
- Prose rules are fixed patterns. They do not detect authorship and cannot judge
  meaning.
- Nothing here grants Gate, publication, or Blessing authority or contacts a
  network or model.
