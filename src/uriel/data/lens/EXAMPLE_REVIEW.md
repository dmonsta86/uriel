# Example: from a loose observation to a research path

## Input

> People in my office seem to make more mistakes after interruptions. Could the
> interruption itself be the cause, and could software help?

## Uriel Lens Review

### Review boundary

[OBSERVED] The supplied material is one informal workplace observation. No
error logs, task definitions, interruption records, participant data, or prior
research were supplied.

### What this project is trying to reach

The immediate question is whether interruptions are associated with measurable
work errors. The stronger testable version asks whether an interruption changes
error rate or completion time for a defined task compared with a matched
uninterrupted condition.

The larger opportunity may be a tool that detects risky interruption timing and
changes how notifications are delivered. That product claim should come after,
not before, the causal question is tested.

### What is already solid

[OBSERVED] There is a repeated pattern worth recording.

[UNKNOWN] The observation does not yet establish frequency, effect size,
causation, or whether the apparent mistakes share a definition.

### Claim and evidence map

| Claim | Evidence supplied | Status | Smallest repair |
|---|---|---|---|
| Interruptions increase mistakes | Informal observation | Unsupported causal claim | Record interruptions and predefined errors during comparable tasks |
| Software could help | None | Not yet testable | Define the intervention and outcome before building it |

### Three-Gate review

**Novelty & Clarity — NEEDS WORK**

“Interruption,” “mistake,” and “office task” are undefined. [PROPOSED] Define an
interruption as an externally triggered task switch lasting at least a chosen
threshold, and define errors before data collection.

**Evidence & Citation — BLOCKED**

No measured evidence was supplied. [PROPOSED] Start with a small within-person
comparison using the same task type, a predefined error rubric, and recorded
interruption timing.

**Adversarial Integrity — NEEDS WORK**

Alternative explanations include fatigue, task difficulty, deadline pressure,
novelty, and people being interrupted precisely when the task is already going
badly. [PROPOSED] Randomize or schedule interruption timing where ethical and
practical, and record task difficulty and time of day.

### Work I can complete now

[PROPOSED] Minimal hypothesis: “For the defined task, participants exposed to a
scheduled interruption will have a higher predefined error rate in the next ten
minutes than during a matched uninterrupted period.”

[PROPOSED] Rival hypothesis: “The apparent increase is explained by task
difficulty or interruption timing rather than the interruption itself.”

[PROPOSED] First result that would count against the idea: no meaningful change
in the predefined error measure across adequately matched conditions.

### Best path forward

- Minimum repair: record the pattern using fixed definitions before making a
  causal claim.
- Best practical path: run a small, ethical, preregistered comparison before
  building notification software.
- Larger opportunity: if the effect survives, test whether timing-aware
  notification delivery reduces errors without creating new harms.

### Next three actions

1. Define the task, interruption, error, and comparison window.
2. Draft a one-page protocol with a rival explanation and stopping rule.
3. Collect a small pilot dataset to test whether the measurement is usable.
